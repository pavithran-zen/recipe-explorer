# Recipe Explorer

A full-stack recipe browsing application with a Node.js/Express REST API and a JavaScript frontend. Users can browse recipes in a photo card grid, search/filter by title, cuisine, rating, and time, view full recipe details in a slide-out panel, and page through results.

## Features

- **REST API** built with Express
  - `GET /api/recipes` — paginated list of recipes, sorted by rating (descending)
  - `GET /api/recipes/search` — filter recipes by title, cuisine, rating, or total time
- **Data cleaning**: invalid or missing numeric fields (rating, prep/cook/total time) are detected during parsing and safely stored as `null` instead of crashing the app or storing bad data
- **Frontend**
  - Photo card grid layout with star ratings
  - Live search by title and cuisine
  - Pagination with adjustable results-per-page (15/20/30/50)
  - Click any recipe to open a detail panel with description, an expandable time breakdown (prep/cook time), and a full nutrition table
  - Graceful empty-state message when no recipes match a search

## Tech stack

- **Backend:** Node.js, Express
- **Data storage:** JSON file (chosen for simplicity and zero external dependencies — see note below)
- **Frontend:** HTML, CSS, vanilla JavaScript (no framework)

## Project structure

```
recipe-app/
├── README.md
├── backend/
│   ├── recipes.json      # raw source data
│   ├── database.json     # cleaned data (generated by seed.js)
│   ├── helpers.js         # NaN-cleaning and filter-parsing utilities
│   ├── seed.js             # parses recipes.json into database.json
│   ├── server.js            # Express server and API routes
│   └── package.json
└── frontend/
    ├── index.html          # page structure
    └── app.js               # fetches from the API and renders the UI
```

## Running the project locally

### 1. Start the backend
```bash
cd backend
npm install
node seed.js       # parses recipes.json into database.json (run once, or after editing recipes.json)
node server.js      # starts the API on http://localhost:4000
```

### 2. Open the frontend
Open `frontend/index.html` directly in a browser (no build step or server needed — it's plain HTML/JS that calls the API over `fetch`).

## API examples

```
GET /api/recipes?page=1&limit=15
GET /api/recipes/search?title=pizza
GET /api/recipes/search?rating=>=4.5
GET /api/recipes/search?cuisine=Italian&total_time=<=45
```

## Design notes

- **Why a JSON file instead of a real database?** For a project this size, a JSON file keeps setup to `npm install` and nothing else — no database server to install or configure. The read/write logic is isolated in helper functions, so swapping in a real database (e.g. PostgreSQL) later would only require changing how data is read/written, not the API logic itself.
- **NaN handling:** raw source data sometimes has `"NaN"` as a string value for numeric fields. `helpers.js` includes a `cleanNumber()` function that converts any invalid or missing numeric value to `null` before it's stored, so the API never returns broken data.
- **Images:** recipe photos are sourced from Unsplash for demonstration purposes.
